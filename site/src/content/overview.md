## TL;DR

我们收集 7000+ 条 Qwen27B-PEAR 的轨迹进行了蒸馏和思维链缩短的尝试并取得了显著效果。同时面对 Embodied AI 领域工作在 RUA 时代暴露出来的首要挑战提出了新的见解————在游戏中测评甚至是训练辅助模型能力的发展。


## 动机

[PEAR](https://github.com/mit-han-lab/pear) 用 5w 卡时的强化学习证明了== Robot Use Agent 能力可以从现有时间节点的小模型的推理中激活的，且 Robot Use Agent 能力在 VLM 中是一个可以和其他通用智能相容的能力。==

同时，VLM RL 出来的 Robot Use Agent 能力和在通用 VLM/Videogen Model 接上 action head 拟合轨迹的 VLA/WAM 有本质的不同：动作轨迹应该是能够被有推理能力的上游理解的，而不是退化成单向的 conditioned flow matching。

PEAR-27B 是一个很好的模型：既被激活了机器人操作能力，又没有失去通用能力。然而，27B 的参数量带来了一定的研究门槛。对于高校和小型实验室来说，用 27B 的模型做高效地受控研究是不现实的。或许 SFT 这种离线算法还好，==所有在 27B 模型上的 on-policy 算法都有着高昂的算力成本，而在过去几年 LLM 领域发生的演进告诉我们 on-policy 的算法具有尚未被发掘完全的巨大优势。==

计算机使用智能体（CUA）先走过这条路：==大模型证明任务的可行性，社区再用蒸馏、合成数据和强化学习把研究搬到小模型上。而这些在小模型上被研究出来的方法一部分又被反哺到 LLM 的研究中。==

我们想在机器人使用智能体（RUA）上做同样的事。PEAR-eLite 从 PEAR-27B 出发，通过 SFT 和 OPD 等方法训练 Qwen3.5-4B/9B 学生，同时缩短教师的思维链。==为 Robot Use Agent 任务提供了更加轻量化的受控基线和修改基座。==

我们做的是一项工程工作：让更多人能在小模型上做更加昂贵的实验。我们期望 Robot Use Agent 能够像 Jev 一样**廉价且可玩性高**，暂且不管大部分研究的质量，==我认为只要思路是正确的，在足够多的社区关注度下，总会有人沉淀出非常优秀的工作！==

## 收集轨迹

我们先用 PEAR-27B 在 LIBERO、LIBERO-Plus 和 LIBERO-Pro 上采样。已经上传的 `rollouts/` 有 6912 局，其中 4454 局成功。每局保留每轮的思维链和动作、机器人状态、两路相机画面和录像。

SFT v2 用的 1250 条成功轨迹就来自这 6912 局：从原版 LIBERO 的 `xhigh` 采样中筛选，排除用于评测的 `trial 0`。

### 蒸馏 Astra 的早期尝试

我们有全网最早用 qwen27B 蒸馏 Astra 轨迹以获取机器人操作能力的尝试记录：https://www.xiaohongshu.com/explore/6ab14b6e0000000036017d7f
使用 8*H200 进行训练。

经过上千条 Astra 轨迹（成功轨迹仅 600 余条）的 SFT 后，Qwen-27B 在最简单的抓取和放置物品、用尺子推方块这类的任务上有着较高的成功率。然而，面对稍微复杂些的任务，它几乎没有成功率。

此外，我们还遇到了以下几个挑战：

#### SFT 数据不够丰富导致过拟合

观察微调后模型的失败轨迹，我们发现模型在未见失败上会开始 Loop，也就是重复输出相似或相同的动作，而忽略环境给的反馈。阅读论文发现这正是在少量数据上轻微过拟合的症状，尽管当时我们使用微调后的模型测试了它的数学能力，并没有显著下降。

解决这个问题最直接的方法自然是使用高质量的数据重新训练。显然当时我们并没有这么多的数据，而Astra的机器人能力也并没有那么强。当然，现在 OAG 各家都推出了具有较强机器人能力的模型。我也看到了有资源的朋友们、前辈们对此的尝试。这条路是可以 work 的，只是需要资源。

一种在当时被我们采纳的方法是加入机器人VQA数据进行训练，以此来缓解过拟合。Captain 的作者和我们同期开始尝试，他也使用了这个方法。但是严格来说是治标不治本的，同时这种 VQA 的正确率也很难直接转化为闭环的成功率。

#### 模型的采样效率问题

在未经大规模强化学习等手段大幅缩短思维链时，不管是小模型 qwen27b 还是大模型 astra 在一次 rollout 上都需要花费不菲的时间，少则 20 分钟，多则 1 小时。而仿真的时间只过了几秒。这是不可接受的。而解决方法正是大规模的强化学习。

#### 环境的 bug

在前Astra时代，也就是VLA、WAM主导的具身智能时代，我们的 benchmark 和测评只是偶尔被喷，容易被 hacking，比如视角不好，比如任务同分布，但这些都只是深入研究这些 benchmark 的人的只言片语。

只要我们能够拟合好轨迹，在训练集上充分拟合，甚至过拟合，就能跑出较高的分数。

直到Agent开始在这些benchmark上进行测评。

9月16日，robodojo 第一个关于 prompt 的 bug 被报道并修复（https://github.com/RoboDojo-Benchmark/RoboDojo/commit/7dae8c7d4100366f85259d135fae808274e094bb
），我在9月11号左右使用Astra进行测评，也观察到了同样的问题。随后的两个月里，又陆续有两次instruction的bug被报道。

其中最让人心惊的是复旦 OpenMOSS 团队的审查，在 RoboDojo 的 42 个仿真任务中，居然有 19 个的 prompt 与实际任务的评判指标明显不同。

这是在前 Agent 时代，不认真考虑指令遵循能力不能发现的事情。而现在，由于 Agentic 的加入，泛化性进一步被推到了一个更高的地位、更高的前提性，这些bug就此被重视。

自从 Robodojo 被 Fable5.2 列为子任务后，对这个 Benchmark 的审查也更加严格。Robodojo Sim 已经是这个领域里面为数不多优秀的 benchmark，但是依旧具有不少的问题 https://p-b-p-b.github.io/blog/2026/what-does-robodojo-really-simulate/ 。

最近几个月 Real2Sim2Real 的管线被各大厂商跑通，但是当前的Agent能力还是很难one-shot跑出可仿真的资产，还是需要大量的 human-in-loop。

同时，机器人在真实场景中需要面临的挑战，比如说长期的记忆、短期的执行（比如实时的控制），以及需要大量视觉推理的挑战，这些benchmark或者 gym 很难面面俱到，又或者产生一些不合理的 bug导致测评和训练的效果变差。

为此，我认为，研究游戏作为一种评测具身智能体的环境，是有前景的。

## SFT / ReOPD 蒸馏

### SFT：先做出能用的学生模型

没训练的学生在这批 LIBERO 评测里是 0/40；用教师轨迹做 SFT 后，**9B 成功 26 局，4B 成功 21 局**。评测用 `xhigh` 档，四个 suite 各 10 局。教师的 29/40 是 FP8 评测结果。

| 模型 | SFT 训练数据 | LIBERO 成功局数 |
| --- | ---: | ---: |
| PEAR-27B（教师） | — | 29 / 40 |
| Qwen3.5-9B-PEAR v2（verl） | 1250 条轨迹 | 26 / 40 |
| Qwen3.5-4B-PEAR v2（verl） | 1250 条轨迹 | 21 / 40 |
| Qwen3.5-4B / 9B（未训练） | — | 0 / 40 |

同用 verl 训练的 9B，388 条轨迹的版本是 22/40，1250 条的版本是 26/40；逐局配对的差异还不显著（McNemar $p = 0.34$）。小模型也不等于少思考：4B v2 每轮平均生成 4907 个 token，比这次评测的教师还多，在长时程的 `libero_10` 上则一局没成功。

### ReOPD：小模型上能跑起来吗？

做完 SFT，我们更想知道的是：**能不能用小模型自己的输出做 on-policy 更新，把这类实验反复跑起来？** 我们先用回放式在线蒸馏（ReOPD）试这条链路。上下文取自教师已记录的轨迹，到了当前轮，由学生用自己的当前策略生成推理和动作，教师再给这些 token 打分，学生据此更新。on-policy 的是这一轮的生成，不是让学生在环境里重新跑完整局；这一步也没有用任务奖励。

采样、打分和参数更新已经接起来，4B 的正式训练还在跑。先看这套流程能否稳定迭代，再把训完的模型和 SFT 起点放在同一批 LIBERO 回合里评测，看任务成功率有没有改善。跑通训练步骤验证的是可用性，闭环评测才用来判断有效性。

## 三阶段思维链退火

这条线改的是 27B 教师，不是上面的 4B / 9B 学生。每阶段让当前模型按指定档位采样，从每个任务的成功轨迹里最多取生成 token 最少的 4 条，做 LoRA 自训练。合并 LoRA 后再进入下一档，顺序是 `xhigh`（A1）、`medium`（A2）、`low`（A3）。三个阶段分别选出 135、48、74 条轨迹。

在 LIBERO 的 `xhigh` 档，A3 的每轮生成 token 从基线 3643 降到 1131，**少了约 69%**；这批评测的成功局数是 29/40 → 32/40（基线 FP8，A3 BF16）。有意思的是，缩短大半在 A1 就做到了，但 A1 在 `low` 档从原模型的 12/40 掉到 4/40。接着训到 A2 是 13/40，训到 A3 是 10/40。最终在 `medium` 和 `low` 档，每轮同样少了约 37% 的 token，成功局数分别是 11 → 12 和 12 → 10。

换到没用于训练的扰动环境，缩短幅度明显小了。LIBERO-Plus 上，A3 和原模型分别成功 32/56 和 35/56，每轮 token 减少约 23%；LIBERO-Pro 上两者都是 21/40，每轮 token 只少约 4%。目前看到的大幅缩短主要发生在训练分布内，没在两组扰动任务上复现。

## 从游戏智能体到 RUA

机器人基准把视觉、物理仿真、推理和成功判定放在一起。LIBERO 的任务分布比较单一，RoboDojo 的物理仿真和成功判定也有限制。一次失败发生在哪个环节，往往不好分辨。游戏可以拆出其中一部分来测，Gamer 等工作也在探索这条路。

我们在[游戏环境分支](https://github.com/Robotic-Agent/PEAR-eLite/tree/feat/game-environments/pear/envs/games)接入了两个游戏。它们沿用 PEAR 的 agent loop 和 JSON 动作通道，但观测、动作和成功判定各由环境定义：

| 环境 | 任务与观测 | 想测试的能力 |
| --- | --- | --- |
| 杀戮尖塔 2 | 纯文本观测，一局需要几十到上百步决策 | 长程记忆、策略推理 |
| Minecraft | 第一人称 RGB 画面，服务端判定是否击中移动红羊 | 实时闭环控制 |

两个环境都已通过接入与冒烟测试，还没跑出模型成绩。Minecraft 现在也只是单任务开发场景。游戏里的结果适合用来查记忆、推理或闭环控制上的问题，能不能迁移，最终还是要回到机器人任务上测。
